# ⚡ Critical Fix: User Registration Persistence & Database Seeding

## المشكلة الحالية:
يقوم المستخدم بإنشاء حساب جديد عبر `/auth/register`، ولكن عند محاولة تسجيل الدخول يظهر أن الحساب غير موجود أو لا يتم حفظه في قاعدة البيانات بالشكل الصحيح، مما يعيق اختبار رحلة العميل.

## المطلوب تنفيذه فوراً (Surgical Fix):
1. **فحص API التسجيل (`/api/auth/register`)**:
   - تأكد من أن عملية الـ `INSERT` إلى جدول ال`users` في قاعدة بيانات MySQL تتم بنجاح ودون أخطاء صامتة (Silent Failures).
   - تحقق من تشفير كلمة المرور (Password Hashing) وتخزين الحقول الإجبارية (`name`, `email`, `password`, `role`).

2. **فحص API تسجيل الدخول (`/api/auth/login`)**:
   - تأكد من أن عملية التحقق من البريد وكلمة المرور تطابق البيانات المسجلة في قاعدة البيانات.
   - تأكد من إنشاء وتعيين الـ JWT Token أو الـ Session Cookie بشكل صحيح (`HttpOnly`, `SameSite=Lax`) لضمان بقاء المستخدم مسجل الدخول عند الانتقال بين الصفحات.

3. **حساب الأدمن الافتراضي (Fallback Admin)**:
   - لضمان إمكانية اختبار لوحة التحكم فوراَ، تأكد من وجود حساب أدمن ثابت في قاعدة البيانات (مثل `admin@y0ussef.com` / `admin123`).

4. **التحقق والبناء**:
   - تشغيل `npx tsc --noEmit` والتأكد من خلوه من الأخطاء.
   - تشغيل `npm run build` للتأكد من سلامة الـ 39 مساراً (Exit Code 0).
   - توثيق الإصلاح في `README.md`.
